# Esther v0.1.0 — first stable deploy

The MVP. Decision-support data only — no order submission anywhere, paper feed locked.

## What it does

A live trading dashboard that helps a discretionary trader understand what's happening across their watchlist faster than they could assemble by hand. Two surfaces over the same intelligence pipeline:

- **Terminal UI** (`esther dashboard`) — full Textual TUI with keybindings (`q r p s o b a x t c ?`), command palette, intraday view toggle, AI briefs (Claude-backed), persistent session state.
- **Web UI** — React + Vite, dense panel grid (watchlist · symbol detail · pulse · opportunities · alerts), live SSE stream, error boundary, exponential-backoff reconnect, stale-data detection.

Same controller pipeline feeds both. JSON contract is the snapshot dataclass.

## Highlights

**Intelligence layer (22 modules)**
RSI / MACD / Bollinger · FinBERT sentiment with quality weighting · 5-tier promoter (`STRONG_BUY` → `STRONG_SELL`) · 7-driver composite opportunity ranker · per-symbol signal history · market pulse with regime classification (risk-on / risk-off / mixed) + trajectory patterns · alerts (4 per-row + 1 snapshot rule + 4 OPP composites + 5 intraday rules) · LLM briefs via `LLMSummarizer` / `LLMOpportunityBriefer` / `LLMRecapGenerator`, all centralized through `grounding.py` anti-hallucination rules.

**Multi-timeframe**
Daily + intraday pipelines in parallel. `t` flips active view in the TUI; every interaction (`o`, `b`, OPP drilldown, alerts) routes through the active timeframe. No cross-view leakage.

**HTTP API**
`GET /api/health` · `GET /api/snapshot` · `GET /api/stream` (Server-Sent Events). One broker per process fans snapshots out to N subscribers via newest-wins queues — never duplicates the controller's tick loop. Heartbeats every ≤15s, reconnect-safe.

**Same-origin deploy**
FastAPI serves `web/dist/` from `/` and the API from `/api/*` on one port. Browsers never make CORS requests. CORS allowlist for the dev workflow (Vite on :5173).

**Persistence**
`SessionStore` v3 atomic JSON snapshot (signal history, OPP membership, pulse history, alert state, tick counter, brief caches). Versioned migrations (v1 → v2 → v3) forward-compatible. Corruption-resilient cold-start.

## Deploy

Railway-ready. `railway.toml` + `nixpacks.toml` pin the build (`pip install -e . && cd web && npm ci && npm run build`) and start (`esther serve --mock --host 0.0.0.0 --port $PORT`) commands. Healthcheck on `/api/health`. First deploy uses `--mock`; flip by setting `ALPACA_API_KEY` / `ALPACA_API_SECRET` / `ALPACA_BASE_URL` / `ANTHROPIC_API_KEY` env vars and dropping `--mock` from the start command.

## Known gaps (Phase 2 candidates)

- No client-side mutations (add-symbol / view-flip via web) — needs auth surface
- Other four panels have no unit tests (vitest is wired; only ErrorBoundary + PulseCard covered)
- No mobile layout (positioning is desktop power-user)
- Bundle could shrink with preact/compat if mobile ever opens up

## Safety posture (unchanged from day one)

- No order submission code anywhere in the codebase
- `is_paper_trading` guard refuses non-paper Alpaca URLs at every actionable entry point
- All LLM calls route through `src/intelligence/grounding.py` — forecast language banned, headlines quoted verbatim, sourced fields only
- `.env` gitignored; `.env.example` is the schema

The build is complete and the deploy works.
